“运行”执行选定的样例测试；“提交”执行该题全部测试。两者都保存尝试记录，只有完整提交全部通过才把题目标记为已解决。

## 前置条件

先[安装本地评测器](install-evaluator.mdx)。打开题目后，保留要求的函数名与参数。线上评测暂不可用。

<Steps>
  <Step title="编写实现">
    在 ReLU 编辑器中输入：

    ```python
    def relu(x):
        return x.clamp(min=0)
    ```

    题目提供的测试负责构造输入并调用函数。不要用打印结果代替返回值。
  </Step>
  <Step title="运行样例">
    在测试面板选择样例并执行“运行”。检查通过数、逐测试耗时和错误信息。样例通过后，题目仍可能保持未解决状态。
  </Step>
  <Step title="提交完整测试">
    执行“提交”。所有测试通过后，检查题目状态和提交历史。已经解决的题目不会因后续失败尝试退回未解决。
  </Step>
</Steps>

## 解释结果

| 结果 | 接下来的操作 |
| --- | --- |
| `passed` | 核对是样例运行还是完整提交 |
| `failed` | 根据失败测试、异常或数值误差调整代码 |
| `timeout` | 检查循环是否终止、输入规模与计算量 |
| `crashed` | 检查评测器状态和错误文本，再重新提交 |
| Busy | 等待当前评测结束后重试 |

应用一次只运行一个评测任务，不在后台无限排队。应用中断后，未完成任务记录为基础设施失败，不会自动重跑。结果和资源字段的定义见[评测协议](../../reference/evaluator/protocol.mdx)。
